11  Naive Bayes and Text Classification

Bayes decision rules, multinomial likelihoods, smoothing, and linear log-odds

Text classification is the supervised learning problem of assigning a label to a document. A document may be an email, review, abstract, news article, student question, or clinical note. In this chapter we develop one of the most important classical models for this task: Naive Bayes. The model is simple, fast, interpretable, and mathematically transparent. Its main lesson is that a probabilistic model for documents can lead to a linear decision rule in word-count features.

11.1 Learning goals

After studying this chapter, you should be able to:

  1. formulate text classification as a statistical decision problem;
  2. derive the Bayes classifier under zero-one loss;
  3. define the multinomial Naive Bayes model for count vectors;
  4. estimate class priors and class-conditional token probabilities from data;
  5. explain the conditional independence assumption and why it is called “naive”;
  6. derive the log-score form \[ s_c(x)=\log \widehat \pi_c+\sum_{j=1}^d x_j\log \widehat \theta_{cj}; \]
  7. show that Naive Bayes is a linear classifier in count-vector space;
  8. implement Naive Bayes from scratch in Python;
  9. use add-\(\alpha\) smoothing to avoid zero probabilities;
  10. evaluate a text classifier with confusion matrices, precision, recall, and \(F_1\) score;
  11. use AI tools to critique assumptions, detect data leakage, and explain classifier behavior.

11.2 Why Naive Bayes matters

Naive Bayes is not a modern large language model. However, it remains a useful mathematical baseline for NLP because it makes the modeling assumptions explicit.

The model answers a clean question:

If documents in class \(c\) generate tokens according to a class-specific probability distribution, which class most likely generated a new document?

This question leads naturally to:

  • Bayes’ theorem;
  • maximum likelihood estimation;
  • multinomial distributions;
  • Dirichlet/additive smoothing;
  • log-likelihood ratios;
  • linear decision boundaries;
  • interpretable feature weights.

Modern neural classifiers often achieve higher accuracy, but Naive Bayes gives a clear first model against which more complicated systems should be compared.

Central idea. A count vector \(x=(x_1,\ldots,x_d)\in \mathbb{N}^d\) records how often each vocabulary token appears in a document. Multinomial Naive Bayes estimates

\[ P(Y=c\mid X=x) \]

by combining a class prior \(P(Y=c)\) with a class-conditional token model \(P(X=x\mid Y=c)\).

11.3 Text classification as a supervised learning problem

Let

\[ \mathcal{Y}=\{1,2,\ldots,K\} \]

be a finite label set. Examples include:

Task Input Label set
sentiment analysis movie review \(\{\text{negative},\text{positive}\}\)
spam detection email \(\{\text{ham},\text{spam}\}\)
topic classification news article \(\{\text{sports},\text{business},\text{science},\ldots\}\)
intent classification student question \(\{\text{transfer credit},\text{course registration},\text{visa},\ldots\}\)

A training dataset is

\[ D_n=\{(d_i,y_i)\}_{i=1}^n, \]

where \(d_i\) is a document and \(y_i\in \mathcal{Y}\) is its label. After choosing a representation map

\[ \phi: \text{documents}\longrightarrow \mathbb{R}^d, \]

we obtain feature vectors

\[ x_i=\phi(d_i)\in \mathbb{R}^d. \]

For Naive Bayes, the most common representation is a count vector:

\[ x_i=(x_{i1},x_{i2},\ldots,x_{id})\in \mathbb{N}^d, \]

where \(x_{ij}\) is the number of times vocabulary token \(v_j\) appears in document \(d_i\).

The goal is to learn a classifier

\[ f:\mathbb{N}^d\longrightarrow \mathcal{Y}. \]

11.4 The Bayes classifier

Assume \((X,Y)\) is a random pair with \(X\in \mathbb{N}^d\) and \(Y\in \mathcal{Y}\). Under zero-one loss,

\[ L(\widehat y,y)= \begin{cases} 0, & \widehat y=y,\\ 1, & \widehat y\neq y, \end{cases} \]

the best possible prediction rule, if the true distribution were known, is the Bayes classifier:

\[ f^*(x)=\arg\max_{c\in \mathcal{Y}} P(Y=c\mid X=x). \]

This rule chooses the class with the largest posterior probability.

By Bayes’ theorem,

\[ P(Y=c\mid X=x) = \frac{P(X=x\mid Y=c)P(Y=c)}{P(X=x)}. \]

For classification, the denominator \(P(X=x)\) does not depend on \(c\). Therefore,

\[ f^*(x)=\arg\max_{c\in \mathcal{Y}} P(X=x\mid Y=c)P(Y=c). \]

This is the maximum a posteriori, or MAP, decision rule.

Bayes decision rule. To classify \(x\), compare the posterior scores

\[ P(X=x\mid Y=c)P(Y=c), \qquad c=1,\ldots,K. \]

Naive Bayes becomes a usable classifier after we specify and estimate the class-conditional distribution \(P(X=x\mid Y=c)\).

11.5 The multinomial event model

Let

\[ V=\{v_1,v_2,\ldots,v_d\} \]

be the vocabulary. In the multinomial Naive Bayes model, each class \(c\) has a token probability vector

\[ \theta_c=(\theta_{c1},\theta_{c2},\ldots,\theta_{cd})\in \Delta^{d-1}, \]

where

\[ \theta_{cj}\ge 0, \qquad \sum_{j=1}^d \theta_{cj}=1. \]

The interpretation is:

\[ \theta_{cj}=P(\text{a randomly drawn token is }v_j\mid Y=c). \]

Now suppose a document has length

\[ m=\sum_{j=1}^d x_j. \]

The multinomial model assumes that, conditional on the class, the document’s tokens are generated by repeated draws from \(\theta_c\). The probability of observing the count vector \(x\) is

\[ P(X=x\mid Y=c) = \frac{m!}{x_1!x_2!\cdots x_d!} \prod_{j=1}^d \theta_{cj}^{x_j}. \]

The multinomial coefficient counts how many token sequences have the same count vector.

For classification, if the document \(x\) is fixed, the coefficient

\[ \frac{m!}{x_1!x_2!\cdots x_d!} \]

does not depend on the class \(c\). Therefore the MAP classifier can ignore it:

\[ \widehat y = \arg\max_{c\in\mathcal{Y}} \pi_c\prod_{j=1}^d \theta_{cj}^{x_j}, \]

where \(\pi_c=P(Y=c)\) is the class prior.

11.6 The conditional independence assumption

The word “naive” refers to the conditional independence assumption. In sequence form, if a document has tokens

\[ w_1,w_2,\ldots,w_m, \]

the model assumes

\[ P(w_1,\ldots,w_m\mid Y=c) \approx \prod_{t=1}^m P(w_t\mid Y=c). \]

That is, after conditioning on the class label, the tokens are treated as independent draws from a class-specific distribution.

This is a strong assumption. Natural language has grammar, word order, collocations, phrases, and long-range dependence. For example, in real text,

not good

is not the same as the two independent words not and good. Yet Naive Bayes often works surprisingly well for topic and sentiment tasks because the presence of highly class-indicative words can dominate the classification score.

Note

The Naive Bayes assumption is usually false as a generative model of language. The important question is not whether the model is literally true, but whether the resulting decision rule is useful and interpretable for a particular task.

11.7 Estimating the parameters

Suppose we have training examples

\[ (x_i,y_i),\qquad i=1,\ldots,n. \]

11.7.1 Class priors

The maximum likelihood estimate of the class prior is

\[ \widehat \pi_c = \frac{n_c}{n}, \]

where

\[ n_c=\sum_{i=1}^n \mathbf{1}\{y_i=c\} \]

is the number of training documents in class \(c\).

11.7.2 Token probabilities

Let

\[ N_{cj}=\sum_{i:y_i=c} x_{ij} \]

be the total number of times token \(v_j\) appears in documents with label \(c\). Let

\[ N_c=\sum_{j=1}^d N_{cj} \]

be the total number of tokens in class \(c\). The maximum likelihood estimate is

\[ \widehat \theta_{cj} = \frac{N_{cj}}{N_c}. \]

11.7.3 Derivation by constrained optimization

For a fixed class \(c\), the likelihood for \(\theta_c\) is proportional to

\[ L_c(\theta_c) = \prod_{j=1}^d \theta_{cj}^{N_{cj}}. \]

The log-likelihood is

\[ \ell_c(\theta_c) = \sum_{j=1}^d N_{cj}\log \theta_{cj}, \]

subject to

\[ \sum_{j=1}^d \theta_{cj}=1. \]

Using a Lagrange multiplier \(\lambda\), define

\[ \mathcal{L}(\theta_c,\lambda) = \sum_{j=1}^d N_{cj}\log \theta_{cj} +\lambda\left(1-\sum_{j=1}^d \theta_{cj}\right). \]

The stationarity condition gives

\[ \frac{\partial \mathcal{L}}{\partial \theta_{cj}} = \frac{N_{cj}}{\theta_{cj}}-\lambda=0. \]

Hence

\[ \theta_{cj}=\frac{N_{cj}}{\lambda}. \]

Summing over \(j\) gives

\[ 1=\sum_{j=1}^d \theta_{cj}=\frac{1}{\lambda}\sum_{j=1}^d N_{cj}=\frac{N_c}{\lambda}, \]

so \(\lambda=N_c\). Therefore

\[ \widehat \theta_{cj}=\frac{N_{cj}}{N_c}. \]

11.8 Zero probabilities and add-\(\alpha\) smoothing

The maximum likelihood estimator assigns probability zero to any token that never appears in class \(c\):

\[ N_{cj}=0 \quad \Longrightarrow \quad \widehat \theta_{cj}=0. \]

This creates a serious problem. If a test document contains even one such token, then

\[ \prod_{j=1}^d \widehat \theta_{cj}^{x_j}=0 \]

for that class. The model may rule out a class entirely because of one unseen word.

To avoid this, we use add-\(\alpha\) smoothing:

\[ \widehat \theta_{cj}^{(\alpha)} = \frac{N_{cj}+\alpha}{N_c+\alpha d}, \qquad \alpha>0. \]

Common choices include \(\alpha=1\) for Laplace smoothing and smaller values such as \(\alpha=0.1\) or \(\alpha=0.01\) for less aggressive smoothing.

11.8.1 Bayesian interpretation

Add-\(\alpha\) smoothing can be interpreted through a symmetric Dirichlet prior on each class token vector:

\[ \theta_c\sim \operatorname{Dirichlet}(\alpha,\ldots,\alpha). \]

The smoothed estimate

\[ \frac{N_{cj}+\alpha}{N_c+\alpha d} \]

is the posterior predictive probability of the next token being \(v_j\) after observing the class-specific token counts.

Smoothing as regularization. Add-\(\alpha\) smoothing shrinks the estimated token distribution away from the boundary of the simplex. No token receives probability zero, so every class remains possible for every document.

11.9 Log-scores and numerical stability

The product

\[ \pi_c\prod_{j=1}^d \theta_{cj}^{x_j} \]

can be extremely small. In computation, multiplying many small probabilities may underflow to zero. Taking logarithms avoids this problem and converts products into sums:

\[ s_c(x) = \log \pi_c+ \sum_{j=1}^d x_j\log \theta_{cj}. \]

The classifier is

\[ \widehat y = \arg\max_{c\in\mathcal{Y}} s_c(x). \]

Because the logarithm is increasing, maximizing the log-score is equivalent to maximizing the original posterior numerator.

11.10 Naive Bayes as a linear classifier

The score for class \(c\) can be written as

\[ s_c(x)=b_c+w_c^\top x, \]

where

\[ b_c=\log \pi_c, \qquad w_c=(\log \theta_{c1},\ldots,\log \theta_{cd})^\top. \]

Thus multinomial Naive Bayes is a linear classifier in count-vector space.

For binary classification with classes \(1\) and \(0\), compare log-scores:

\[ s_1(x)-s_0(x) = \log\frac{\pi_1}{\pi_0} + \sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}. \]

The decision rule is

\[ \widehat y=1 \quad \Longleftrightarrow \quad \log\frac{\pi_1}{\pi_0} + \sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}>0. \]

The decision boundary is the hyperplane

\[ \log\frac{\pi_1}{\pi_0} + \sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}=0. \]

Tip

The weights

\[ \log\frac{\theta_{1j}}{\theta_{0j}} \]

are interpretable. A large positive value means token \(v_j\) strongly favors class \(1\) over class \(0\). A large negative value means the token strongly favors class \(0\).

11.11 Relation to logistic regression

Both Naive Bayes and logistic regression can produce linear decision boundaries, but they estimate different objects.

Naive Bayes is a generative model. It estimates

\[ P(Y=c), \qquad P(X=x\mid Y=c), \]

and then uses Bayes’ theorem to obtain a classifier.

Logistic regression is a discriminative model. It estimates the conditional probability directly:

\[ P(Y=c\mid X=x). \]

For binary classification, logistic regression models

\[ P(Y=1\mid X=x) = \sigma(\beta_0+\beta^\top x), \]

where

\[ \sigma(z)=\frac{1}{1+e^{-z}}. \]

Naive Bayes may work well with small data because it imposes strong probabilistic structure. Logistic regression may work better with enough labeled data because it directly optimizes conditional prediction.

11.12 Bernoulli Naive Bayes

The multinomial model uses token counts. Another common model uses binary features:

\[ z_j=\mathbf{1}\{\text{token }v_j\text{ appears in the document}\}. \]

For each class \(c\), Bernoulli Naive Bayes estimates

\[ \rho_{cj}=P(Z_j=1\mid Y=c). \]

The class-conditional probability is

\[ P(Z=z\mid Y=c) = \prod_{j=1}^d \rho_{cj}^{z_j}(1-\rho_{cj})^{1-z_j}. \]

The log-score becomes

\[ s_c(z) = \log \pi_c+ \sum_{j=1}^d \left[z_j\log \rho_{cj}+(1-z_j)\log(1-\rho_{cj})\right]. \]

Bernoulli Naive Bayes models word presence or absence; multinomial Naive Bayes models word counts. For longer documents, multinomial Naive Bayes is often more natural. For short texts, binary presence features can be useful.

11.13 Worked example by hand

Suppose the vocabulary is

\[ V=\{\texttt{win},\texttt{meeting},\texttt{free}\}. \]

There are two classes:

\[ \mathcal{Y}=\{\text{spam},\text{ham}\}. \]

Assume the estimated parameters are:

\[ \widehat \pi_{\text{spam}}=0.4, \qquad \widehat \pi_{\text{ham}}=0.6, \]

and

token \(\widehat\theta_{\text{spam},j}\) \(\widehat\theta_{\text{ham},j}\)
win 0.50 0.05
meeting 0.05 0.70
free 0.45 0.25

Consider the document

free win free

Its count vector is

\[ x=(1,0,2). \]

The spam log-score is

\[ \log(0.4)+1\log(0.50)+0\log(0.05)+2\log(0.45). \]

The ham log-score is

\[ \log(0.6)+1\log(0.05)+0\log(0.70)+2\log(0.25). \]

Since win and free are much more likely under the spam token distribution, the spam score will be larger.

11.14 Python example: training from scratch

The following code implements multinomial Naive Bayes without using a machine learning library. The point is to see the mathematical quantities directly.

import re
from collections import Counter, defaultdict
import numpy as np
import pandas as pd

train_docs = [
    ("free money win now", "spam"),
    ("win a free prize", "spam"),
    ("cheap offer free entry", "spam"),
    ("meeting schedule for project", "ham"),
    ("project meeting tomorrow", "ham"),
    ("please review the project schedule", "ham"),
]

test_docs = [
    "free project prize",
    "meeting tomorrow schedule",
    "win free offer",
    "please review money",
]

def tokenize(text):
    return re.findall(r"[a-z]+", text.lower())

# Build vocabulary from training documents.
vocab = sorted({tok for doc, label in train_docs for tok in tokenize(doc)})
token_to_index = {tok: j for j, tok in enumerate(vocab)}
classes = sorted({label for _, label in train_docs})

print("Vocabulary:", vocab)

Define prediction using log-scores.

def vectorize(doc):
    x = np.zeros(d, dtype=float)
    for tok in tokenize(doc):
        if tok in token_to_index:
            x[token_to_index[tok]] += 1
    return x

def log_scores(doc):
    x = vectorize(doc)
    scores = {}
    for c in classes:
        scores[c] = np.log(priors[c]) + np.sum(x * np.log(theta[c]))
    return scores

def predict(doc):
    scores = log_scores(doc)
    return max(scores, key=scores.get), scores

for doc in test_docs:

11.16 Python example: accuracy and confusion matrix

Here is a tiny evaluation example. In a real project, train and test sets should be separated carefully.

labeled_test = [
    ("free project prize", "spam"),
    ("meeting tomorrow schedule", "ham"),
    ("win free offer", "spam"),
    ("please review money", "ham"),
]

confusion = pd.DataFrame(0, index=classes, columns=classes)
correct = 0

for doc, true_label in labeled_test:
    pred_label, _ = predict(doc)
    confusion.loc[true_label, pred_label] += 1
    correct += int(pred_label == true_label)

accuracy = correct / len(labeled_test)
print("Accuracy:", accuracy)
print(confusion)

For binary classification with positive class spam, define:

\[ \text{precision}=\frac{TP}{TP+FP}, \qquad \text{recall}=\frac{TP}{TP+FN}, \]

and

\[ F_1=\frac{2\cdot \text{precision}\cdot \text{recall}}{\text{precision}+\text{recall}}. \]

pos = "spam"

precision = TP / (TP + FP) if TP + FP > 0 else 0.0
recall = TP / (TP + FN) if TP + FN > 0 else 0.0
f1 = 2 * precision * recall / (precision + recall) if precision + recall > 0 else 0.0

    "recall": round(float(recall), 3),
    "f1": round(float(f1), 3),
})

11.18 Statistical interpretation of smoothing

Smoothing changes a classifier in two ways.

First, it prevents impossible events. Every token receives positive probability in every class:

\[ \widehat \theta_{cj}^{(\alpha)}>0. \]

Second, it reduces the magnitude of extreme log-odds weights. If a token appears many times in one class and zero times in another, the unsmoothed log-ratio would be infinite. Smoothing makes the ratio finite:

\[ \log\frac{N_{1j}+\alpha}{N_{0j}+\alpha} + \log\frac{N_0+\alpha d}{N_1+\alpha d}. \]

Thus smoothing acts like a regularizer on the classifier’s feature weights.

11.19 Model assumptions and failure modes

Naive Bayes works best when class-indicative tokens are strong and word order is not essential. It can fail when meaning depends on syntax, negation, or context.

11.19.1 Failure mode 1: negation

The phrases

good

and

not good

have different meanings. A unigram Naive Bayes model may treat good as positive even when preceded by not.

Possible remedy: add bigram features such as not_good.

11.19.2 Failure mode 2: repeated correlated words

Because Naive Bayes multiplies token probabilities, repeated correlated words may make the model overconfident. The model behaves as though each occurrence contributes independent evidence.

Possible remedy: use binary features, stronger smoothing, feature selection, or a discriminative model.

11.19.3 Failure mode 3: dataset leakage

If the training data contains label artifacts, the classifier may learn shortcuts. For example, if all spam examples contain a footer phrase not present at deployment time, the model may appear accurate in validation but fail in practice.

Possible remedy: inspect feature weights and validate on realistic held-out data.

11.21 A complete mathematical summary

The multinomial Naive Bayes pipeline can be summarized as follows.

  1. Choose a vocabulary

\[ V=\{v_1,\ldots,v_d\}. \]

  1. Represent each document as a count vector

\[ x\in \mathbb{N}^d. \]

  1. Estimate class priors

\[ \widehat \pi_c=\frac{n_c}{n}. \]

  1. Estimate smoothed token probabilities

\[ \widehat \theta_{cj} = \frac{N_{cj}+\alpha}{N_c+\alpha d}. \]

  1. Compute class log-scores

\[ s_c(x)=\log \widehat \pi_c+ \sum_{j=1}^d x_j\log \widehat \theta_{cj}. \]

  1. Predict

\[ \widehat y=\arg\max_{c\in\mathcal{Y}}s_c(x). \]

The classifier is probabilistic in origin but linear in its final scoring form.

## Why Naive Bayes matters

Naive Bayes is not a modern large language model.  However, it remains a useful mathematical baseline for NLP because it makes the modeling assumptions explicit.

The model answers a clean question:

> If documents in class $c$ generate tokens according to a class-specific probability distribution, which class most likely generated a new document?

This question leads naturally to:

- Bayes' theorem;
- maximum likelihood estimation;
- multinomial distributions;
- Dirichlet/additive smoothing;
- log-likelihood ratios;
- linear decision boundaries;
- interpretable feature weights.

Modern neural classifiers often achieve higher accuracy, but Naive Bayes gives a clear first model against which more complicated systems should be compared.

::: {.math-card}
**Central idea.**  A count vector $x=(x_1,\ldots,x_d)\in \mathbb{N}^d$ records how often each vocabulary token appears in a document.  Multinomial Naive Bayes estimates

$$
P(Y=c\mid X=x)
$$

by combining a class prior $P(Y=c)$ with a class-conditional token model $P(X=x\mid Y=c)$.
:::

## Text classification as a supervised learning problem

Let

$$
\mathcal{Y}=\{1,2,\ldots,K\}
$$

be a finite label set.  Examples include:

| Task | Input | Label set |
|---|---|---|
| sentiment analysis | movie review | $\{\text{negative},\text{positive}\}$ |
| spam detection | email | $\{\text{ham},\text{spam}\}$ |
| topic classification | news article | $\{\text{sports},\text{business},\text{science},\ldots\}$ |
| intent classification | student question | $\{\text{transfer credit},\text{course registration},\text{visa},\ldots\}$ |

A training dataset is

$$
D_n=\{(d_i,y_i)\}_{i=1}^n,
$$

where $d_i$ is a document and $y_i\in \mathcal{Y}$ is its label.  After choosing a representation map

$$
\phi: \text{documents}\longrightarrow \mathbb{R}^d,
$$

we obtain feature vectors

$$
x_i=\phi(d_i)\in \mathbb{R}^d.
$$

For Naive Bayes, the most common representation is a count vector:

$$
x_i=(x_{i1},x_{i2},\ldots,x_{id})\in \mathbb{N}^d,
$$

where $x_{ij}$ is the number of times vocabulary token $v_j$ appears in document $d_i$.

The goal is to learn a classifier

$$
f:\mathbb{N}^d\longrightarrow \mathcal{Y}.
$$

## The Bayes classifier

Assume $(X,Y)$ is a random pair with $X\in \mathbb{N}^d$ and $Y\in \mathcal{Y}$.  Under zero-one loss,

$$
L(\widehat y,y)=
\begin{cases}
0, & \widehat y=y,\\
1, & \widehat y\neq y,
\end{cases}
$$

the best possible prediction rule, if the true distribution were known, is the **Bayes classifier**:

$$
f^*(x)=\arg\max_{c\in \mathcal{Y}} P(Y=c\mid X=x).
$$

This rule chooses the class with the largest posterior probability.

By Bayes' theorem,

$$
P(Y=c\mid X=x)
=
\frac{P(X=x\mid Y=c)P(Y=c)}{P(X=x)}.
$$

For classification, the denominator $P(X=x)$ does not depend on $c$.  Therefore,

$$
f^*(x)=\arg\max_{c\in \mathcal{Y}} P(X=x\mid Y=c)P(Y=c).
$$

This is the maximum a posteriori, or MAP, decision rule.

::: {.math-card}
**Bayes decision rule.**  To classify $x$, compare the posterior scores

$$
P(X=x\mid Y=c)P(Y=c), \qquad c=1,\ldots,K.
$$

Naive Bayes becomes a usable classifier after we specify and estimate the class-conditional distribution $P(X=x\mid Y=c)$.
:::

## The multinomial event model

Let

$$
V=\{v_1,v_2,\ldots,v_d\}
$$

be the vocabulary.  In the multinomial Naive Bayes model, each class $c$ has a token probability vector

$$
\theta_c=(\theta_{c1},\theta_{c2},\ldots,\theta_{cd})\in \Delta^{d-1},
$$

where

$$
\theta_{cj}\ge 0, \qquad \sum_{j=1}^d \theta_{cj}=1.
$$

The interpretation is:

$$
\theta_{cj}=P(\text{a randomly drawn token is }v_j\mid Y=c).
$$

Now suppose a document has length

$$
m=\sum_{j=1}^d x_j.
$$

The multinomial model assumes that, conditional on the class, the document's tokens are generated by repeated draws from $\theta_c$.  The probability of observing the count vector $x$ is

$$
P(X=x\mid Y=c)
=
\frac{m!}{x_1!x_2!\cdots x_d!}
\prod_{j=1}^d \theta_{cj}^{x_j}.
$$

The multinomial coefficient counts how many token sequences have the same count vector.

For classification, if the document $x$ is fixed, the coefficient

$$
\frac{m!}{x_1!x_2!\cdots x_d!}
$$

does not depend on the class $c$.  Therefore the MAP classifier can ignore it:

$$
\widehat y
=
\arg\max_{c\in\mathcal{Y}}
\pi_c\prod_{j=1}^d \theta_{cj}^{x_j},
$$

where $\pi_c=P(Y=c)$ is the class prior.

## The conditional independence assumption

The word "naive" refers to the conditional independence assumption.  In sequence form, if a document has tokens

$$
w_1,w_2,\ldots,w_m,
$$

the model assumes

$$
P(w_1,\ldots,w_m\mid Y=c)
\approx
\prod_{t=1}^m P(w_t\mid Y=c).
$$

That is, after conditioning on the class label, the tokens are treated as independent draws from a class-specific distribution.

This is a strong assumption.  Natural language has grammar, word order, collocations, phrases, and long-range dependence.  For example, in real text,

```text
not good
```

is not the same as the two independent words `not` and `good`.  Yet Naive Bayes often works surprisingly well for topic and sentiment tasks because the presence of highly class-indicative words can dominate the classification score.

::: {.callout-note}
The Naive Bayes assumption is usually false as a generative model of language.  The important question is not whether the model is literally true, but whether the resulting decision rule is useful and interpretable for a particular task.
:::

## Estimating the parameters

Suppose we have training examples

$$
(x_i,y_i),\qquad i=1,\ldots,n.
$$

### Class priors

The maximum likelihood estimate of the class prior is

$$
\widehat \pi_c
=
\frac{n_c}{n},
$$

where

$$
n_c=\sum_{i=1}^n \mathbf{1}\{y_i=c\}
$$

is the number of training documents in class $c$.

### Token probabilities

Let

$$
N_{cj}=\sum_{i:y_i=c} x_{ij}
$$

be the total number of times token $v_j$ appears in documents with label $c$.  Let

$$
N_c=\sum_{j=1}^d N_{cj}
$$

be the total number of tokens in class $c$.  The maximum likelihood estimate is

$$
\widehat \theta_{cj}
=
\frac{N_{cj}}{N_c}.
$$

### Derivation by constrained optimization

For a fixed class $c$, the likelihood for $\theta_c$ is proportional to

$$
L_c(\theta_c)
=
\prod_{j=1}^d \theta_{cj}^{N_{cj}}.
$$

The log-likelihood is

$$
\ell_c(\theta_c)
=
\sum_{j=1}^d N_{cj}\log \theta_{cj},
$$

subject to

$$
\sum_{j=1}^d \theta_{cj}=1.
$$

Using a Lagrange multiplier $\lambda$, define

$$
\mathcal{L}(\theta_c,\lambda)
=
\sum_{j=1}^d N_{cj}\log \theta_{cj}
+\lambda\left(1-\sum_{j=1}^d \theta_{cj}\right).
$$

The stationarity condition gives

$$
\frac{\partial \mathcal{L}}{\partial \theta_{cj}}
=
\frac{N_{cj}}{\theta_{cj}}-\lambda=0.
$$

Hence

$$
\theta_{cj}=\frac{N_{cj}}{\lambda}.
$$

Summing over $j$ gives

$$
1=\sum_{j=1}^d \theta_{cj}=\frac{1}{\lambda}\sum_{j=1}^d N_{cj}=\frac{N_c}{\lambda},
$$

so $\lambda=N_c$.  Therefore

$$
\widehat \theta_{cj}=\frac{N_{cj}}{N_c}.
$$

## Zero probabilities and add-$\alpha$ smoothing

The maximum likelihood estimator assigns probability zero to any token that never appears in class $c$:

$$
N_{cj}=0 \quad \Longrightarrow \quad \widehat \theta_{cj}=0.
$$

This creates a serious problem.  If a test document contains even one such token, then

$$
\prod_{j=1}^d \widehat \theta_{cj}^{x_j}=0
$$

for that class.  The model may rule out a class entirely because of one unseen word.

To avoid this, we use add-$\alpha$ smoothing:

$$
\widehat \theta_{cj}^{(\alpha)}
=
\frac{N_{cj}+\alpha}{N_c+\alpha d},
\qquad \alpha>0.
$$

Common choices include $\alpha=1$ for Laplace smoothing and smaller values such as $\alpha=0.1$ or $\alpha=0.01$ for less aggressive smoothing.

### Bayesian interpretation

Add-$\alpha$ smoothing can be interpreted through a symmetric Dirichlet prior on each class token vector:

$$
\theta_c\sim \operatorname{Dirichlet}(\alpha,\ldots,\alpha).
$$

The smoothed estimate

$$
\frac{N_{cj}+\alpha}{N_c+\alpha d}
$$

is the posterior predictive probability of the next token being $v_j$ after observing the class-specific token counts.

::: {.math-card}
**Smoothing as regularization.**  Add-$\alpha$ smoothing shrinks the estimated token distribution away from the boundary of the simplex.  No token receives probability zero, so every class remains possible for every document.
:::

## Log-scores and numerical stability

The product

$$
\pi_c\prod_{j=1}^d \theta_{cj}^{x_j}
$$

can be extremely small.  In computation, multiplying many small probabilities may underflow to zero.  Taking logarithms avoids this problem and converts products into sums:

$$
s_c(x)
=
\log \pi_c+
\sum_{j=1}^d x_j\log \theta_{cj}.
$$

The classifier is

$$
\widehat y
=
\arg\max_{c\in\mathcal{Y}} s_c(x).
$$

Because the logarithm is increasing, maximizing the log-score is equivalent to maximizing the original posterior numerator.

## Naive Bayes as a linear classifier

The score for class $c$ can be written as

$$
s_c(x)=b_c+w_c^\top x,
$$

where

$$
b_c=\log \pi_c,
\qquad
w_c=(\log \theta_{c1},\ldots,\log \theta_{cd})^\top.
$$

Thus multinomial Naive Bayes is a linear classifier in count-vector space.

For binary classification with classes $1$ and $0$, compare log-scores:

$$
s_1(x)-s_0(x)
=
\log\frac{\pi_1}{\pi_0}
+
\sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}.
$$

The decision rule is

$$
\widehat y=1
\quad \Longleftrightarrow \quad
\log\frac{\pi_1}{\pi_0}
+
\sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}>0.
$$

The decision boundary is the hyperplane

$$
\log\frac{\pi_1}{\pi_0}
+
\sum_{j=1}^d x_j\log\frac{\theta_{1j}}{\theta_{0j}}=0.
$$

::: {.callout-tip}
The weights

$$
\log\frac{\theta_{1j}}{\theta_{0j}}
$$

are interpretable.  A large positive value means token $v_j$ strongly favors class $1$ over class $0$.  A large negative value means the token strongly favors class $0$.
:::

## Relation to logistic regression

Both Naive Bayes and logistic regression can produce linear decision boundaries, but they estimate different objects.

Naive Bayes is a **generative** model.  It estimates

$$
P(Y=c),
\qquad
P(X=x\mid Y=c),
$$

and then uses Bayes' theorem to obtain a classifier.

Logistic regression is a **discriminative** model.  It estimates the conditional probability directly:

$$
P(Y=c\mid X=x).
$$

For binary classification, logistic regression models

$$
P(Y=1\mid X=x)
=
\sigma(\beta_0+\beta^\top x),
$$

where

$$
\sigma(z)=\frac{1}{1+e^{-z}}.
$$

Naive Bayes may work well with small data because it imposes strong probabilistic structure.  Logistic regression may work better with enough labeled data because it directly optimizes conditional prediction.

## Bernoulli Naive Bayes

The multinomial model uses token counts.  Another common model uses binary features:

$$
z_j=\mathbf{1}\{\text{token }v_j\text{ appears in the document}\}.
$$

For each class $c$, Bernoulli Naive Bayes estimates

$$
\rho_{cj}=P(Z_j=1\mid Y=c).
$$

The class-conditional probability is

$$
P(Z=z\mid Y=c)
=
\prod_{j=1}^d \rho_{cj}^{z_j}(1-\rho_{cj})^{1-z_j}.
$$

The log-score becomes

$$
s_c(z)
=
\log \pi_c+
\sum_{j=1}^d
\left[z_j\log \rho_{cj}+(1-z_j)\log(1-\rho_{cj})\right].
$$

Bernoulli Naive Bayes models word presence or absence; multinomial Naive Bayes models word counts.  For longer documents, multinomial Naive Bayes is often more natural.  For short texts, binary presence features can be useful.

## Worked example by hand

Suppose the vocabulary is

V=\{\texttt{win},\texttt{meeting},\texttt{free}\}.

There are two classes:

$$
\mathcal{Y}=\{\text{spam},\text{ham}\}.

Assume the estimated parameters are:

\widehat \pi_{\text{spam}}=0.4,
\qquad
\widehat \pi_{\text{ham}}=0.6,
$$

and

| token | $\widehat\theta_{\text{spam},j}$ | $\widehat\theta_{\text{ham},j}$ |
|---|---:|---:|
| `win` | 0.50 | 0.05 |
| `meeting` | 0.05 | 0.70 |
| `free` | 0.45 | 0.25 |

Consider the document

```text
free win free
```

Its count vector is

$$
x=(1,0,2).
$$

The spam log-score is

$$
\log(0.4)+1\log(0.50)+0\log(0.05)+2\log(0.45).
$$

The ham log-score is

$$
\log(0.6)+1\log(0.05)+0\log(0.70)+2\log(0.25).
$$

Since `win` and `free` are much more likely under the spam token distribution, the spam score will be larger.

## Python example: training from scratch

The following code implements multinomial Naive Bayes without using a machine learning library.  The point is to see the mathematical quantities directly.

```{python}
import re
from collections import Counter, defaultdict
import numpy as np
import pandas as pd

train_docs = [
    ("free money win now", "spam"),
    ("win a free prize", "spam"),
    ("cheap offer free entry", "spam"),
    ("meeting schedule for project", "ham"),
    ("project meeting tomorrow", "ham"),
    ("please review the project schedule", "ham"),
]

test_docs = [
    "free project prize",
    "meeting tomorrow schedule",
    "win free offer",
    "please review money",
]

def tokenize(text):
    return re.findall(r"[a-z]+", text.lower())

# Build vocabulary from training documents.
vocab = sorted({tok for doc, label in train_docs for tok in tokenize(doc)})
token_to_index = {tok: j for j, tok in enumerate(vocab)}
classes = sorted({label for _, label in train_docs})

print("Vocabulary:", vocab)
print("Classes:", classes)
```

Now estimate the class priors and class-conditional token distributions.

```{python}
alpha = 1.0
K = len(classes)
d = len(vocab)

class_doc_counts = Counter(label for _, label in train_docs)
class_token_counts = {c: np.zeros(d, dtype=float) for c in classes}
class_total_tokens = {c: 0.0 for c in classes}

for doc, label in train_docs:
    for tok in tokenize(doc):
        j = token_to_index[tok]
        class_token_counts[label][j] += 1
        class_total_tokens[label] += 1

priors = {c: class_doc_counts[c] / len(train_docs) for c in classes}
theta = {}
for c in classes:
    theta[c] = (class_token_counts[c] + alpha) / (class_total_tokens[c] + alpha * d)

prior_table = pd.DataFrame({"class": classes, "prior": [priors[c] for c in classes]})
print(prior_table)

theta_table = pd.DataFrame(theta, index=vocab)
print(theta_table.round(3))
```

Define prediction using log-scores.

```{python}
def vectorize(doc):
    x = np.zeros(d, dtype=float)
    for tok in tokenize(doc):
        if tok in token_to_index:
            x[token_to_index[tok]] += 1
    return x

def log_scores(doc):
    x = vectorize(doc)
    scores = {}
    for c in classes:
        scores[c] = np.log(priors[c]) + np.sum(x * np.log(theta[c]))
    return scores

def predict(doc):
    scores = log_scores(doc)
    return max(scores, key=scores.get), scores

for doc in test_docs:
    pred, scores = predict(doc)
    print(f"Document: {doc!r}")
    print("Prediction:", pred)
    print("Scores:", {c: round(scores[c], 3) for c in classes})
    print()
```

positive_class = "spam"

## Python example: accuracy and confusion matrix

Here is a tiny evaluation example.  In a real project, train and test sets should be separated carefully.

```{python}
labeled_test = [
    ("free project prize", "spam"),
    ("meeting tomorrow schedule", "ham"),
    ("win free offer", "spam"),
    ("please review money", "ham"),
]

confusion = pd.DataFrame(0, index=classes, columns=classes)
correct = 0

for doc, true_label in labeled_test:
    pred_label, _ = predict(doc)
    confusion.loc[true_label, pred_label] += 1
    correct += int(pred_label == true_label)

```

For binary classification with positive class `spam`, define:

$$
\text{precision}=\frac{TP}{TP+FP},
\qquad
\text{recall}=\frac{TP}{TP+FN},
$$

and

$$
F_1=\frac{2\cdot \text{precision}\cdot \text{recall}}{\text{precision}+\text{recall}}.
$$

```{python}
pos = "spam"
neg = "ham"
TP = confusion.loc[pos, pos]
FP = confusion.loc[neg, pos]
FN = confusion.loc[pos, neg]

precision = TP / (TP + FP) if TP + FP > 0 else 0.0
recall = TP / (TP + FN) if TP + FN > 0 else 0.0
f1 = 2 * precision * recall / (precision + recall) if precision + recall > 0 else 0.0

print({
    "precision": round(float(precision), 3),
    "recall": round(float(recall), 3),
    "f1": round(float(f1), 3),
})
```

## Statistical interpretation of smoothing

Smoothing changes a classifier in two ways.

First, it prevents impossible events.  Every token receives positive probability in every class:

$$
\widehat \theta_{cj}^{(\alpha)}>0.
$$

Second, it reduces the magnitude of extreme log-odds weights.  If a token appears many times in one class and zero times in another, the unsmoothed log-ratio would be infinite.  Smoothing makes the ratio finite:

$$
\log\frac{N_{1j}+\alpha}{N_{0j}+\alpha}
+
\log\frac{N_0+\alpha d}{N_1+\alpha d}.
$$

Thus smoothing acts like a regularizer on the classifier's feature weights.

## Model assumptions and failure modes

Naive Bayes works best when class-indicative tokens are strong and word order is not essential.  It can fail when meaning depends on syntax, negation, or context.

### Failure mode 1: negation

The phrases

```text
good
```

and

```text
not good
```

have different meanings.  A unigram Naive Bayes model may treat `good` as positive even when preceded by `not`.

Possible remedy: add bigram features such as `not_good`.

### Failure mode 2: repeated correlated words

Because Naive Bayes multiplies token probabilities, repeated correlated words may make the model overconfident.  The model behaves as though each occurrence contributes independent evidence.

Possible remedy: use binary features, stronger smoothing, feature selection, or a discriminative model.

### Failure mode 3: dataset leakage

If the training data contains label artifacts, the classifier may learn shortcuts.  For example, if all spam examples contain a footer phrase not present at deployment time, the model may appear accurate in validation but fail in practice.

Possible remedy: inspect feature weights and validate on realistic held-out data.

## A complete mathematical summary

The multinomial Naive Bayes pipeline can be summarized as follows.

1. Choose a vocabulary

$$
V=\{v_1,\ldots,v_d\}.
$$

2. Represent each document as a count vector

$$
x\in \mathbb{N}^d.
$$

3. Estimate class priors

$$
\widehat \pi_c=\frac{n_c}{n}.
$$

4. Estimate smoothed token probabilities

$$
\widehat \theta_{cj}
=
\frac{N_{cj}+\alpha}{N_c+\alpha d}.
$$

5. Compute class log-scores

$$
s_c(x)=\log \widehat \pi_c+
\sum_{j=1}^d x_j\log \widehat \theta_{cj}.
$$

6. Predict

$$
\widehat y=\arg\max_{c\in\mathcal{Y}}s_c(x).
$$

The classifier is probabilistic in origin but linear in its final scoring form.

## What to remember

- Naive Bayes is a generative classifier: it models $P(Y)$ and $P(X\mid Y)$.
- The multinomial model treats a document as a bag of token counts.
- The conditional independence assumption is mathematically convenient but linguistically false.
- Add-$\alpha$ smoothing prevents zero probabilities and regularizes log-odds weights.
- The MAP rule becomes a linear classifier in count-vector space.
- The feature weights are interpretable through log-ratios of class-conditional token probabilities.
- Naive Bayes is a useful baseline before using larger neural NLP models.
