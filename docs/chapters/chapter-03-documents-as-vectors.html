8  Documents as Vectors

Term-document matrices, TF-IDF, and cosine geometry

After text has been tokenized, the next classical step in NLP is to represent each document by a vector. This chapter develops document vectors from a mathematical point of view. We build count vectors, term-document matrices, normalized frequency vectors, TF-IDF vectors, and cosine similarity. The goal is not only to compute these objects, but to understand what assumptions they encode and why they still matter in modern AI systems such as search engines and retrieval-augmented generation.

8.1 Learning goals

After studying this chapter, you should be able to:

  1. define a document-vector representation as a map from token sequences to \(R^d\);
  2. construct count vectors and document-term matrices from a corpus;
  3. distinguish counts, binary indicators, relative frequencies, and normalized vectors;
  4. explain TF-IDF as a mathematical weighting scheme for term specificity;
  5. compute cosine similarity and interpret it geometrically;
  6. rank documents in response to a query using sparse vector operations;
  7. describe the statistical assumptions behind bag-of-words models;
  8. implement document-vector methods in Python without relying on black-box NLP libraries;
  9. use interactive visualizations to study how TF-IDF and normalization change retrieval;
  10. use AI tools critically to test, explain, and improve vector-space representations.

8.2 Why documents become vectors

A document is naturally a sequence of tokens. If the vocabulary is

\[ V = \{v_1,v_2,\ldots,v_d\}, \]

then a tokenized document has the form

\[ x=(t_1,t_2,\ldots,t_m), \qquad t_k \in V. \]

Many mathematical and statistical methods, however, operate on vectors and matrices. The basic idea of this chapter is to replace a token sequence by a vector

\[ \phi(x) \in R^d, \]

where the \(j\)th coordinate measures how strongly token \(v_j\) appears in the document.

Central idea. A document-vector model is a representation map

\[ \phi:V^* \to R^d. \]

Different choices of \(\phi\) produce different mathematical models. Count vectors, TF-IDF vectors, binary vectors, probability vectors, and neural embeddings are all representation maps.

The simplest representation ignores word order and records only token counts. Although this loses information, it produces a useful finite-dimensional object. In classical NLP and information retrieval, this is called the vector space model.

8.3 Corpus, vocabulary, and notation

Let

\[ D = (x_1,x_2,\ldots,x_n) \]

be a corpus of \(n\) tokenized documents. Each document \(x_i\) is a finite sequence over the vocabulary \(V\).

We use the following notation throughout the chapter:

Symbol Meaning
\(n\) number of documents
\(d\) vocabulary size
\(x_i\) document \(i\)
\(v_j\) vocabulary token \(j\)
\(c_{ij}\) count of token \(v_j\) in document \(x_i\)
\(X\) document-term matrix
\(q\) query vector
\(s_i\) similarity score between document \(i\) and query

The central matrix is

\[ X = (c_{ij}) \in R^{n \times d}, \]

where

\[ c_{ij}=\#\{k : t_{ik}=v_j\}. \]

Here \(t_{ik}\) is the \(k\)th token in document \(x_i\).

8.3.1 Row convention

In this book we usually use the row convention:

\[ X_{i\cdot} = \text{vector representation of document } x_i. \]

Thus each row is a document and each column is a term. Some books use the transpose convention, where columns are documents. Both are valid, but dimensions must be tracked carefully.

Dimension check. If \(X \in R^{n \times d}\) and a query vector is \(q \in R^d\), then raw document-query scores have the form

\[ Xq \in R^n. \]

The output contains one score for each document.

8.4 Count vectors

The count vector of a document \(x\) is

\[ c(x)=(c_1(x),c_2(x),\ldots,c_d(x)) \in N^d, \]

where

\[ c_j(x)=\#\{k:t_k=v_j\}. \]

For example, suppose

\[ V=\{\text{data},\text{language},\text{learning},\text{models},\text{token}\}. \]

If

data data learning models

is the document, then

\[ c(x)=(2,0,1,1,0). \]

The count vector answers the question: How many times does each vocabulary term appear?

8.4.1 What counts preserve and lose

The count vector preserves token frequency but discards order. For example, the two documents

models predict language

and

language predict models

have the same count vector. Therefore, the count-vector map is not injective.

Bag-of-words assumption. A count vector treats a document as a multiset of tokens rather than as an ordered sequence. Mathematically, this means the representation is invariant under permutations of the token positions.

If \(\pi\) is a permutation of \(\{1,2,\ldots,m\}\) and

\[ x=(t_1,t_2,\ldots,t_m), \]

then the permuted document

\[ \pi x=(t_{\pi(1)},t_{\pi(2)},\ldots,t_{\pi(m)}) \]

satisfies

\[ c(\pi x)=c(x). \]

This invariance is both a strength and a weakness. It makes the model simple and robust, but it cannot distinguish syntax, negation, or word order.

8.5 Binary vectors

Sometimes we care only whether a token appears, not how often. The binary representation is

\[ b_j(x)= \begin{cases} 1, & c_j(x)>0,\\ 0, & c_j(x)=0. \end{cases} \]

Thus

\[ b(x) \in \{0,1\}^d. \]

Binary vectors are useful when repeated occurrences should not dominate. For example, if one document repeats the word “model” many times, a raw count vector may make it appear overly similar to any query containing “model.” Binary vectors reduce this effect.

8.6 Relative-frequency vectors

Raw counts depend strongly on document length. If one document is twice as long as another, its count vector may have a larger norm simply because it contains more words. A simple correction is to divide by the document length.

Let

\[ |x| = \sum_{j=1}^d c_j(x) \]

be the total number of vocabulary tokens in document \(x\). The relative-frequency vector is

\[ p_j(x)=\frac{c_j(x)}{|x|}, \qquad j=1,\ldots,d. \]

Then

\[ p(x) \in R^d, \qquad p_j(x)\ge 0, \qquad \sum_{j=1}^d p_j(x)=1. \]

Thus \(p(x)\) is an empirical probability distribution over the vocabulary.

Statistical viewpoint. If a document is modeled as a sample from a multinomial distribution over \(V\), then the relative-frequency vector is the maximum likelihood estimate of the token probability vector for that document.

This interpretation connects document vectors to statistics. A document is not merely a string; it can be viewed as data generated by an unknown distribution on words.

8.7 The document-term matrix

Given \(n\) documents and \(d\) vocabulary terms, the count vectors form a matrix

\[ X = \begin{bmatrix} --- & c(x_1)^T & ---\\ --- & c(x_2)^T & ---\\ & \vdots & \\ --- & c(x_n)^T & --- \end{bmatrix} \in R^{n\times d}. \]

Equivalently,

\[ X_{ij}=c_j(x_i). \]

This matrix is usually sparse because most documents contain only a small fraction of all vocabulary terms.

8.7.1 Example

Consider the corpus

  1. machine learning models learn from data
  2. language models predict the next token
  3. statistics studies data uncertainty and models

Using the vocabulary

\[ V=\{\text{data},\text{language},\text{learning},\text{models},\text{predict},\text{statistics},\text{token}\}, \]

the document-term matrix is

\[ X= \begin{bmatrix} 1&0&1&1&0&0&0\\ 0&1&0&1&1&0&1\\ 1&0&0&1&0&1&0 \end{bmatrix}. \]

The first row says that the first document contains data, learning, and models once each.

8.8 Python example: building a document-term matrix

The following code builds a vocabulary and document-term matrix from scratch. This is useful because it exposes the mathematical object directly.

import re
import numpy as np
import pandas as pd

corpus = [
    "machine learning models learn from data",
    "language models predict the next token",
    "statistics studies data uncertainty and models",
    "learning from data helps statistical models",
]

def tokenize(text):
    text = text.lower()
    return re.findall(r"[a-z]+", text)

tokenized = [tokenize(doc) for doc in corpus]

# Build vocabulary in alphabetical order for reproducibility.
vocab = sorted(set(token for doc in tokenized for token in doc))
token_to_id = {token: j for j, token in enumerate(vocab)}

X = np.zeros((len(corpus), len(vocab)), dtype=int)
for i, doc in enumerate(tokenized):
    for token in doc:
        X[i, token_to_id[token]] += 1

X_df = pd.DataFrame(X, columns=vocab, index=[f"doc_{i+1}" for i in range(len(corpus))])
print(X_df)

The output matrix is the basic object used by many classical NLP algorithms. Notice that the matrix construction requires only tokenization, a vocabulary map, and counting.

8.9 Linear algebra viewpoint

Once documents are represented as vectors, we can use linear algebra.

Let

\[ x,y \in R^d \]

be two document vectors. We may compute:

  • their dot product \(x^Ty\);
  • their norms \(\|x\|_1\), \(\|x\|_2\), or \(\|x\|_\infty\);
  • their angle through cosine similarity;
  • their distance, such as \(\|x-y\|_2\);
  • their projection onto a low-dimensional subspace.

The dot product is

\[ x^Ty=\sum_{j=1}^d x_jy_j. \]

For count vectors, this quantity is large when the two documents share many terms with high counts.

However, dot products are sensitive to length. A longer document tends to have a larger norm and may receive a large dot product even when it is not especially similar in content.

8.10 Cosine similarity

Cosine similarity normalizes by vector length:

\[ \operatorname{cos}(x,y)=\frac{x^Ty}{\|x\|_2\|y\|_2}, \]

provided \(x\ne 0\) and \(y\ne 0\).

Geometrically, this is the cosine of the angle between \(x\) and \(y\). It measures direction rather than magnitude. If \(x\) and \(y\) point in the same direction, then their cosine similarity is \(1\). If they are orthogonal, the similarity is \(0\).

For nonnegative document vectors, cosine similarity lies between \(0\) and \(1\).

Scale invariance. For any \(a>0\) and \(b>0\),

\[ \operatorname{cos}(ax,by)=\operatorname{cos}(x,y). \]

Therefore, cosine similarity ignores positive rescaling of documents. This is useful when document lengths differ.

8.10.1 Matrix form of cosine retrieval

Suppose \(X\in R^{n\times d}\) contains document vectors and \(q\in R^d\) is a query vector. The raw dot-product scores are

\[ r=Xq \in R^n. \]

The cosine scores are

\[ s_i=\frac{X_{i\cdot}q}{\|X_{i\cdot}\|_2\|q\|_2}, \qquad i=1,\ldots,n. \]

If we define the row-normalized matrix

\[ \widetilde X_{i\cdot}=\frac{X_{i\cdot}}{\|X_{i\cdot}\|_2} \]

and the normalized query

\[ \widetilde q=\frac{q}{\|q\|_2}, \]

then

\[ s=\widetilde X\widetilde q. \]

Thus retrieval by cosine similarity is matrix-vector multiplication after normalization.

8.11 Python example: cosine search

import numpy as np
import pandas as pd
import re

corpus = [
    "machine learning models learn from data",
    "language models predict the next token",
    "statistics studies data uncertainty and models",
    "learning from data helps statistical models",
]

def tokenize(text):
    return re.findall(r"[a-z]+", text.lower())

tokenized = [tokenize(doc) for doc in corpus]
vocab = sorted(set(token for doc in tokenized for token in doc))
token_to_id = {token: j for j, token in enumerate(vocab)}

def vectorize(tokens):
    vec = np.zeros(len(vocab))
    for token in tokens:
        if token in token_to_id:
            vec[token_to_id[token]] += 1
    return vec

X = np.vstack([vectorize(doc) for doc in tokenized])

query = "data learning models"
q = vectorize(tokenize(query))

def cosine_similarity_matrix(X, q):
    q_norm = np.linalg.norm(q)
    X_norms = np.linalg.norm(X, axis=1)
    scores = X @ q
    scores = scores / (X_norms * q_norm)
    return scores

scores = cosine_similarity_matrix(X, q)
ranking = np.argsort(-scores)

for rank, i in enumerate(ranking, start=1):
    print(f"{rank}. score={scores[i]:.3f} | {corpus[i]}")

This code shows that document retrieval can be written as a small linear algebra problem.

8.12 Term frequency

Raw counts can be transformed before similarity is computed. The first transformation is term frequency.

A simple term frequency is

\[ \operatorname{tf}_{ij}=c_{ij}. \]

A length-normalized term frequency is

\[ \operatorname{tf}_{ij}=\frac{c_{ij}}{\sum_{k=1}^d c_{ik}}. \]

A log-scaled term frequency is

\[ \operatorname{tf}_{ij}= \begin{cases} 1+\log(c_{ij}), & c_{ij}>0,\\ 0, & c_{ij}=0. \end{cases} \]

The log transform reduces the effect of repeated occurrences. For example, a term appearing ten times should not always be ten times as important as a term appearing once.

8.13 Document frequency and inverse document frequency

Some words appear in many documents. These common terms often have low discriminative value. For example, words such as the, and, model, or data may appear frequently in a technical corpus.

The document frequency of token \(v_j\) is

\[ \operatorname{df}_j=\#\{i:c_{ij}>0\}. \]

It counts how many documents contain the term at least once.

The inverse document frequency is commonly defined as

\[ \operatorname{idf}_j=\log\left(\frac{n+1}{\operatorname{df}_j+1}\right)+1. \]

The added \(1\) in numerator and denominator is smoothing. It avoids division by zero and keeps the weight finite. Other conventions are also used.

Interpretation. If \(\operatorname{df}_j/n\) is the empirical probability that a random document contains token \(v_j\), then

\[ \log\left(\frac{n}{\operatorname{df}_j}\right) \]

is the negative logarithm of this empirical probability. Rare terms receive larger weights because they are more informative for distinguishing documents.

8.14 TF-IDF vectors

The TF-IDF weight of term \(v_j\) in document \(x_i\) is

\[ w_{ij}=\operatorname{tf}_{ij}\operatorname{idf}_j. \]

In matrix form, if \(T=(\operatorname{tf}_{ij})\) and

\[ D_{\operatorname{idf}}=\operatorname{diag}(\operatorname{idf}_1,\ldots,\operatorname{idf}_d), \]

then the TF-IDF matrix is

\[ W=TD_{\operatorname{idf}}. \]

This is a column weighting of the term-frequency matrix. Terms that appear in many documents get smaller weights. Terms that appear in fewer documents get larger weights.

8.14.1 Why TF-IDF is useful

TF-IDF balances two effects:

  1. Within-document importance. A term is important if it appears often in a particular document.
  2. Across-document specificity. A term is more informative if it does not appear in almost every document.

Thus TF-IDF is a simple way to say:

A good keyword should be frequent in this document but not too frequent across the whole corpus.

8.15 Python example: TF-IDF from scratch

import numpy as np
import pandas as pd

# X is the document-term count matrix from the previous example.
n, d = X.shape

# Term frequency: length-normalized counts.
doc_lengths = X.sum(axis=1, keepdims=True)
TF = X / doc_lengths

# Document frequency.
df = (X > 0).sum(axis=0)

# Smoothed inverse document frequency.
idf = np.log((n + 1) / (df + 1)) + 1

# TF-IDF matrix.
W = TF * idf

W_df = pd.DataFrame(W, columns=vocab, index=[f"doc_{i+1}" for i in range(n)])
print(W_df.round(3))

The resulting matrix has the same shape as the count matrix, but its entries have changed. Common tokens receive smaller column weights, while more specific tokens receive larger column weights.

8.16 Comparing count vectors and TF-IDF vectors

Count vectors often reward documents that share common terms with the query. TF-IDF vectors reward documents that share more specific terms.

Suppose the query is

language token prediction

A count-vector search might rank a document highly because it contains language and token. TF-IDF may increase the importance of token if it appears in only a few documents.

This distinction matters in academic settings. For example, in a corpus of course descriptions, words such as course, students, and methods may appear everywhere. Words such as Bayesian, topology, or transformer may be more specific.

8.18 The geometry of sparse document vectors

Document vectors often live in very high dimensions. A vocabulary may contain thousands or millions of tokens, while a single document uses only a small subset. Therefore, most entries of a document vector are zero.

This creates a sparse geometry:

\[ \#\{j:x_j\ne 0\} \ll d. \]

Sparse vectors are computationally useful because we do not need to store or multiply by all zero entries. They are also geometrically interesting. Two randomly chosen short documents may have no terms in common, which makes their dot product zero.

8.18.1 Orthogonality in sparse spaces

If two count vectors have disjoint supports, then

\[ x^Ty=0. \]

For nonnegative vectors, this means their cosine similarity is zero. In a large vocabulary, many pairs of documents may be nearly orthogonal even if they are topically related but use different words.

For example, the documents

neural network training

and

deep learning optimization

are semantically related, but a simple bag-of-words model may give low similarity if the exact words do not overlap. This limitation motivates later chapters on latent semantic analysis, word embeddings, and transformer representations.

8.19 Stop words and projection

A common preprocessing step removes very frequent words such as the, and, of, and to. Mathematically, stop-word removal is a coordinate projection.

Let \(S\subseteq \{1,2,\ldots,d\}\) be the set of coordinates corresponding to terms we keep. The projection map is

\[ P_S:R^d\to R^{|S|}, \]

where

\[ P_S(x)=(x_j)_{j\in S}. \]

This map discards coordinates. It can improve retrieval by removing noise, but it can also remove meaningful words in some contexts. For example, not is often a stop word in generic lists, but it is crucial for sentiment analysis.

Modeling warning. Stop-word removal is not universally safe. It is a projection that may remove coordinates relevant to the task.

8.20 Statistical model behind bag-of-words

The bag-of-words representation can be derived from a multinomial model.

Suppose document \(x_i\) has length \(m_i\) and is generated by independent draws from a categorical distribution

\[ \theta_i=(\theta_{i1},\ldots,\theta_{id}), \]

where

\[ \theta_{ij}\ge 0, \qquad \sum_{j=1}^d \theta_{ij}=1. \]

The probability of observing counts

\[ c_i=(c_{i1},\ldots,c_{id}) \]

is

\[ P(c_i\mid \theta_i)=\frac{m_i!}{c_{i1}!c_{i2}!\cdots c_{id}!}\prod_{j=1}^d \theta_{ij}^{c_{ij}}. \]

The log-likelihood, ignoring the multinomial coefficient, is

\[ \ell(\theta_i)=\sum_{j=1}^d c_{ij}\log \theta_{ij}. \]

Maximizing this subject to \(\sum_j \theta_{ij}=1\) gives

\[ \widehat\theta_{ij}=\frac{c_{ij}}{m_i}. \]

Thus the relative-frequency vector is the maximum likelihood estimate of the document’s token distribution under this simplified model.

8.20.1 What the model assumes

The multinomial bag-of-words model assumes:

  1. token order is irrelevant;
  2. tokens are conditionally independent given \(\theta_i\);
  3. each document has its own word distribution;
  4. dependence between neighboring words is ignored.

These assumptions are false for real language, but they give a mathematically transparent baseline.

8.21 Connection to classification

Document vectors are not only used for retrieval. They can also be used for classification.

Suppose each document has a label

\[ y_i\in \{1,2,\ldots,K\}. \]

A linear classifier has the form

\[ f(x_i)=\arg\max_{k\in\{1,\ldots,K\}} \left(w_k^T\phi(x_i)+b_k\right). \]

Here \(\phi(x_i)\) may be a count vector, TF-IDF vector, or another document representation. The same vectorization step supports logistic regression, support vector machines, naive Bayes, and neural networks.

For binary classification, a common model is

\[ P(y_i=1\mid x_i)=\sigma(w^T\phi(x_i)+b), \]

where

\[ \sigma(z)=\frac{1}{1+e^{-z}}. \]

This shows how vector-space NLP connects directly to statistics and machine learning.

8.22 Low-dimensional visualization by SVD

Because document vectors are high-dimensional, we often visualize them by projecting to two dimensions. A simple method is singular value decomposition.

Let \(W\in R^{n\times d}\) be a centered or weighted document-term matrix. Its singular value decomposition is

\[ W=U\Sigma V^T. \]

The best rank-\(k\) approximation in Frobenius norm is

\[ W_k=U_k\Sigma_kV_k^T. \]

For visualization, we often use the rows of

\[ U_2\Sigma_2\in R^{n\times 2} \]

as two-dimensional document coordinates.

Preview. This idea leads to latent semantic analysis, which studies low-rank structure in document-term matrices. Chapter 7 returns to this topic in detail.

8.23 Python example: two-dimensional document map

import numpy as np
import matplotlib.pyplot as plt

# Use the TF-IDF matrix W from the earlier example.
# Center columns so the SVD highlights differences among documents.
W_centered = W - W.mean(axis=0, keepdims=True)

U, S, Vt = np.linalg.svd(W_centered, full_matrices=False)
coords = U[:, :2] * S[:2]

plt.figure(figsize=(6, 4))
plt.scatter(coords[:, 0], coords[:, 1])
for i, text in enumerate(corpus):
    plt.annotate(f"doc_{i+1}", (coords[i, 0], coords[i, 1]))
plt.axhline(0, linewidth=0.8)
plt.axvline(0, linewidth=0.8)
plt.xlabel("first SVD coordinate")
plt.ylabel("second SVD coordinate")
plt.title("Documents projected to two dimensions")
plt.show()

This visualization is not a replacement for the full high-dimensional representation. It is a diagnostic tool that helps us inspect whether documents cluster by topic or vocabulary.

8.24 Evaluation of retrieval

A document-vector method is often used for retrieval: given a query, return a ranked list of documents. To evaluate retrieval, we need relevance judgments.

For a query \(q\), let

\[ R(q)\subseteq \{1,2,\ldots,n\} \]

be the set of relevant documents. If a system returns the top \(k\) documents

\[ A_k(q), \]

then precision at \(k\) is

\[ \operatorname{Precision@}k=\frac{|A_k(q)\cap R(q)|}{k}. \]

Recall at \(k\) is

\[ \operatorname{Recall@}k=\frac{|A_k(q)\cap R(q)|}{|R(q)|}. \]

Precision measures how many retrieved documents are relevant. Recall measures how many relevant documents were retrieved.

For course search, advising chatbots, and RAG systems, retrieval evaluation is essential. A language model can only answer from useful evidence if the retrieval step finds useful evidence.

8.25 AI component: document vectors in RAG systems

Modern retrieval-augmented generation systems often use neural embeddings rather than TF-IDF. However, the mathematical pipeline is similar:

\[ \text{document} \xrightarrow{\phi} R^p, \qquad \text{query} \xrightarrow{\phi} R^p, \qquad \text{rank by similarity}. \]

In classical vector search, \(\phi\) may be TF-IDF. In neural vector search, \(\phi\) may be a transformer embedding model. The retrieval step still depends on geometry: dot products, cosine similarity, nearest neighbors, and ranking.

AI-assisted learning activity. Ask an AI system:

Give three short documents for which TF-IDF search succeeds and three short documents for which TF-IDF search fails. For each failure, explain the mathematical reason in terms of vocabulary overlap, synonymy, negation, or word order.

Then verify the examples by computing count vectors and cosine similarities yourself.

8.26 AI component: auditing a representation

When using AI tools to help build NLP systems, ask the tool to make the representation assumptions explicit. A useful prompt is:

I am representing documents using TF-IDF vectors. List the mathematical assumptions of this representation. Which assumptions are problematic for sentiment analysis, course advising, and mathematical text search?

A good answer should mention at least:

  • loss of word order;
  • dependence on exact vocabulary overlap;
  • sensitivity to tokenization;
  • inability to understand synonyms unless they share terms;
  • possible removal of important stop words;
  • limited handling of negation;
  • dependence on the corpus used to compute IDF.

Use AI tools as mathematical critics, not as replacements for mathematical verification.

8.27 Worked example: hand calculation

Consider three documents with vocabulary

\[ V=\{a,b,c,d\}. \]

Suppose the count matrix is

\[ X= \begin{bmatrix} 2&1&0&0\\ 1&0&2&0\\ 0&1&0&3 \end{bmatrix}. \]

Let the query be

\[ q=(1,1,0,0)^T. \]

The raw dot-product scores are

\[ Xq= \begin{bmatrix} 3\\ 1\\ 1 \end{bmatrix}. \]

The Euclidean norms are

\[ \|q\|_2=\sqrt{2}, \]

\[ \|X_{1\cdot}\|_2=\sqrt{5}, \qquad \|X_{2\cdot}\|_2=\sqrt{5}, \qquad \|X_{3\cdot}\|_2=\sqrt{10}. \]

Thus the cosine scores are

\[ s_1=\frac{3}{\sqrt{5}\sqrt{2}}=\frac{3}{\sqrt{10}}, \]

\[ s_2=\frac{1}{\sqrt{5}\sqrt{2}}=\frac{1}{\sqrt{10}}, \]

and

\[ s_3=\frac{1}{\sqrt{10}\sqrt{2}}=\frac{1}{\sqrt{20}}. \]

Therefore, document 1 is most similar to the query.

This small example illustrates the full retrieval calculation: vectorize, multiply, normalize, rank.

8.28 Common pitfalls

8.28.1 Pitfall 1: confusing rows and columns

Always state whether documents are rows or columns. In this book, documents are rows.

8.28.2 Pitfall 2: forgetting zero vectors

Cosine similarity is undefined when one vector has zero norm. This can happen if a query contains no vocabulary terms.

8.28.3 Pitfall 3: assuming TF-IDF understands meaning

TF-IDF is a lexical method. It does not know that doctor and physician are related unless the corpus and vocabulary create indirect associations.

8.28.4 Pitfall 4: ignoring corpus dependence

IDF weights depend on the corpus. If the corpus changes, the IDF weights change.

8.28.5 Pitfall 5: treating preprocessing as neutral

Lowercasing, punctuation removal, stop-word removal, and stemming all change the mathematical representation.

8.29 Chapter summary

The main construction in this chapter is the document-vector map

\[ \phi:V^*\to R^d. \]

The simplest choice is the count vector. From count vectors we build the document-term matrix

\[ X\in R^{n\times d}. \]

We then transform this matrix using normalization and TF-IDF weighting. Similarity between documents or between a query and documents is often measured by cosine similarity:

\[ \operatorname{cos}(x,y)=\frac{x^Ty}{\|x\|_2\|y\|_2}. \]

These ideas form the classical foundation of search and retrieval. They also prepare us for modern NLP, where documents and queries are represented by learned dense vectors instead of sparse TF-IDF vectors.

## Why documents become vectors

A document is naturally a sequence of tokens.  If the vocabulary is

$$
V = \{v_1,v_2,\ldots,v_d\},
$$

then a tokenized document has the form

$$
x=(t_1,t_2,\ldots,t_m), \qquad t_k \in V.
$$

Many mathematical and statistical methods, however, operate on vectors and matrices.  The basic idea of this chapter is to replace a token sequence by a vector

$$
\phi(x) \in R^d,
$$

where the $j$th coordinate measures how strongly token $v_j$ appears in the document.

::: {.math-card}
**Central idea.**  A document-vector model is a representation map

$$
\phi:V^* \to R^d.
$$

Different choices of $\phi$ produce different mathematical models.  Count vectors, TF-IDF vectors, binary vectors, probability vectors, and neural embeddings are all representation maps.
:::

The simplest representation ignores word order and records only token counts.  Although this loses information, it produces a useful finite-dimensional object.  In classical NLP and information retrieval, this is called the **vector space model**.

## Corpus, vocabulary, and notation

Let

$$
D = (x_1,x_2,\ldots,x_n)
$$

be a corpus of $n$ tokenized documents.  Each document $x_i$ is a finite sequence over the vocabulary $V$.

We use the following notation throughout the chapter:

| Symbol | Meaning |
|---|---|
| $n$ | number of documents |
| $d$ | vocabulary size |
| $x_i$ | document $i$ |
| $v_j$ | vocabulary token $j$ |
| $c_{ij}$ | count of token $v_j$ in document $x_i$ |
| $X$ | document-term matrix |
| $q$ | query vector |
| $s_i$ | similarity score between document $i$ and query |

The central matrix is

$$
X = (c_{ij}) \in R^{n \times d},
$$

where

$$
c_{ij}=\#\{k : t_{ik}=v_j\}.
$$

Here $t_{ik}$ is the $k$th token in document $x_i$.

### Row convention

In this book we usually use the row convention:

$$
X_{i\cdot} = \text{vector representation of document } x_i.
$$

Thus each row is a document and each column is a term.  Some books use the transpose convention, where columns are documents.  Both are valid, but dimensions must be tracked carefully.

::: {.math-card}
**Dimension check.**  If $X \in R^{n \times d}$ and a query vector is $q \in R^d$, then raw document-query scores have the form

$$
Xq \in R^n.
$$

The output contains one score for each document.
:::

## Count vectors

The count vector of a document $x$ is

$$
c(x)=(c_1(x),c_2(x),\ldots,c_d(x)) \in N^d,
$$

where

$$
c_j(x)=\#\{k:t_k=v_j\}.
$$

For example, suppose

$$
V=\{\text{data},\text{language},\text{learning},\text{models},\text{token}\}.
$$

If

```text
data data learning models
```

is the document, then

$$
c(x)=(2,0,1,1,0).
$$

The count vector answers the question: **How many times does each vocabulary term appear?**

### What counts preserve and lose

The count vector preserves token frequency but discards order.  For example, the two documents

```text
models predict language
```

and

```text
language predict models
```

have the same count vector.  Therefore, the count-vector map is not injective.

::: {.math-card}
**Bag-of-words assumption.**  A count vector treats a document as a multiset of tokens rather than as an ordered sequence.  Mathematically, this means the representation is invariant under permutations of the token positions.
:::

If $\pi$ is a permutation of $\{1,2,\ldots,m\}$ and

$$
x=(t_1,t_2,\ldots,t_m),
$$

then the permuted document

$$
\pi x=(t_{\pi(1)},t_{\pi(2)},\ldots,t_{\pi(m)})
$$

satisfies

$$
c(\pi x)=c(x).
$$

This invariance is both a strength and a weakness.  It makes the model simple and robust, but it cannot distinguish syntax, negation, or word order.

## Binary vectors

Sometimes we care only whether a token appears, not how often.  The binary representation is

$$
b_j(x)=
\begin{cases}
1, & c_j(x)>0,\\
0, & c_j(x)=0.
\end{cases}
$$

Thus

$$
b(x) \in \{0,1\}^d.
$$

Binary vectors are useful when repeated occurrences should not dominate.  For example, if one document repeats the word "model" many times, a raw count vector may make it appear overly similar to any query containing "model."  Binary vectors reduce this effect.

## Relative-frequency vectors

Raw counts depend strongly on document length.  If one document is twice as long as another, its count vector may have a larger norm simply because it contains more words.  A simple correction is to divide by the document length.

Let

$$
|x| = \sum_{j=1}^d c_j(x)
$$

be the total number of vocabulary tokens in document $x$.  The relative-frequency vector is

$$
p_j(x)=\frac{c_j(x)}{|x|}, \qquad j=1,\ldots,d.
$$

Then

$$
p(x) \in R^d, \qquad p_j(x)\ge 0, \qquad \sum_{j=1}^d p_j(x)=1.
$$

Thus $p(x)$ is an empirical probability distribution over the vocabulary.

::: {.math-card}
**Statistical viewpoint.**  If a document is modeled as a sample from a multinomial distribution over $V$, then the relative-frequency vector is the maximum likelihood estimate of the token probability vector for that document.
:::

This interpretation connects document vectors to statistics.  A document is not merely a string; it can be viewed as data generated by an unknown distribution on words.

## The document-term matrix

Given $n$ documents and $d$ vocabulary terms, the count vectors form a matrix

$$
X =
\begin{bmatrix}
--- & c(x_1)^T & ---\\
--- & c(x_2)^T & ---\\
& \vdots & \\
--- & c(x_n)^T & ---
\end{bmatrix}
\in R^{n\times d}.
$$

Equivalently,

$$
X_{ij}=c_j(x_i).
$$

This matrix is usually sparse because most documents contain only a small fraction of all vocabulary terms.

### Example

Consider the corpus

1. `machine learning models learn from data`
2. `language models predict the next token`
3. `statistics studies data uncertainty and models`

Using the vocabulary

$$
V=\{\text{data},\text{language},\text{learning},\text{models},\text{predict},\text{statistics},\text{token}\},
$$

the document-term matrix is

$$
X=
\begin{bmatrix}
1&0&1&1&0&0&0\\
0&1&0&1&1&0&1\\
1&0&0&1&0&1&0
\end{bmatrix}.
$$

The first row says that the first document contains `data`, `learning`, and `models` once each.

The following code builds a vocabulary and document-term matrix from scratch.  This is useful because it exposes the mathematical object directly.

## Linear algebra viewpoint

Once documents are represented as vectors, we can use linear algebra.

Let

$$
x,y \in R^d
$$

be two document vectors.  We may compute:

- their dot product $x^Ty$;
- their norms $\|x\|_1$, $\|x\|_2$, or $\|x\|_\infty$;
- their angle through cosine similarity;
- their distance, such as $\|x-y\|_2$;
- their projection onto a low-dimensional subspace.

The dot product is

$$
x^Ty=\sum_{j=1}^d x_jy_j.
$$

For count vectors, this quantity is large when the two documents share many terms with high counts.

However, dot products are sensitive to length.  A longer document tends to have a larger norm and may receive a large dot product even when it is not especially similar in content.

## Cosine similarity

Cosine similarity normalizes by vector length:

$$
\operatorname{cos}(x,y)=\frac{x^Ty}{\|x\|_2\|y\|_2},
$$

provided $x\ne 0$ and $y\ne 0$.

Geometrically, this is the cosine of the angle between $x$ and $y$.  It measures direction rather than magnitude.  If $x$ and $y$ point in the same direction, then their cosine similarity is $1$.  If they are orthogonal, the similarity is $0$.

For nonnegative document vectors, cosine similarity lies between $0$ and $1$.

::: {.math-card}
**Scale invariance.**  For any $a>0$ and $b>0$,

$$
\operatorname{cos}(ax,by)=\operatorname{cos}(x,y).
$$

Therefore, cosine similarity ignores positive rescaling of documents.  This is useful when document lengths differ.
:::

### Matrix form of cosine retrieval

Suppose $X\in R^{n\times d}$ contains document vectors and $q\in R^d$ is a query vector.  The raw dot-product scores are

$$
r=Xq \in R^n.
$$

The cosine scores are

$$
s_i=\frac{X_{i\cdot}q}{\|X_{i\cdot}\|_2\|q\|_2}, \qquad i=1,\ldots,n.
$$

If we define the row-normalized matrix

$$
\widetilde X_{i\cdot}=\frac{X_{i\cdot}}{\|X_{i\cdot}\|_2}
$$

and the normalized query

$$
\widetilde q=\frac{q}{\|q\|_2},
$$

then

$$
s=\widetilde X\widetilde q.
$$

Thus retrieval by cosine similarity is matrix-vector multiplication after normalization.

## Python example: cosine search

```{python}
#| label: ch03-cosine-search
#| echo: true
#| eval: false

import numpy as np
import pandas as pd
import re

corpus = [
    "machine learning models learn from data",
    "language models predict the next token",
    "statistics studies data uncertainty and models",
    "learning from data helps statistical models",
]

def tokenize(text):
    return re.findall(r"[a-z]+", text.lower())

tokenized = [tokenize(doc) for doc in corpus]
vocab = sorted(set(token for doc in tokenized for token in doc))
token_to_id = {token: j for j, token in enumerate(vocab)}

def vectorize(tokens):
    vec = np.zeros(len(vocab))
    for token in tokens:
        if token in token_to_id:
            vec[token_to_id[token]] += 1
    return vec

X = np.vstack([vectorize(doc) for doc in tokenized])

query = "data learning models"
q = vectorize(tokenize(query))

def cosine_similarity_matrix(X, q):
    q_norm = np.linalg.norm(q)
    X_norms = np.linalg.norm(X, axis=1)
    scores = X @ q
    scores = scores / (X_norms * q_norm)
    return scores

scores = cosine_similarity_matrix(X, q)
ranking = np.argsort(-scores)

for rank, i in enumerate(ranking, start=1):
    print(f"{rank}. score={scores[i]:.3f} | {corpus[i]}")
```

This code shows that document retrieval can be written as a small linear algebra problem.

## Term frequency

Raw counts can be transformed before similarity is computed.  The first transformation is **term frequency**.

A simple term frequency is

$$
\operatorname{tf}_{ij}=c_{ij}.
$$

A length-normalized term frequency is

$$
\operatorname{tf}_{ij}=\frac{c_{ij}}{\sum_{k=1}^d c_{ik}}.
$$

A log-scaled term frequency is

$$
\operatorname{tf}_{ij}=
\begin{cases}
1+\log(c_{ij}), & c_{ij}>0,\\
0, & c_{ij}=0.
\end{cases}
$$

The log transform reduces the effect of repeated occurrences.  For example, a term appearing ten times should not always be ten times as important as a term appearing once.

## Document frequency and inverse document frequency

Some words appear in many documents.  These common terms often have low discriminative value.  For example, words such as `the`, `and`, `model`, or `data` may appear frequently in a technical corpus.

The document frequency of token $v_j$ is

$$
\operatorname{df}_j=\#\{i:c_{ij}>0\}.
$$

It counts how many documents contain the term at least once.

The inverse document frequency is commonly defined as

$$
\operatorname{idf}_j=\log\left(\frac{n+1}{\operatorname{df}_j+1}\right)+1.
$$

The added $1$ in numerator and denominator is smoothing.  It avoids division by zero and keeps the weight finite.  Other conventions are also used.

::: {.math-card}
**Interpretation.**  If $\operatorname{df}_j/n$ is the empirical probability that a random document contains token $v_j$, then

$$
\log\left(\frac{n}{\operatorname{df}_j}\right)
$$

is the negative logarithm of this empirical probability.  Rare terms receive larger weights because they are more informative for distinguishing documents.
:::

## TF-IDF vectors

The TF-IDF weight of term $v_j$ in document $x_i$ is

$$
w_{ij}=\operatorname{tf}_{ij}\operatorname{idf}_j.
$$

In matrix form, if $T=(\operatorname{tf}_{ij})$ and

$$
D_{\operatorname{idf}}=\operatorname{diag}(\operatorname{idf}_1,\ldots,\operatorname{idf}_d),
$$

then the TF-IDF matrix is

$$
W=TD_{\operatorname{idf}}.
$$

This is a column weighting of the term-frequency matrix.  Terms that appear in many documents get smaller weights.  Terms that appear in fewer documents get larger weights.

### Why TF-IDF is useful

TF-IDF balances two effects:

1. **Within-document importance.**  A term is important if it appears often in a particular document.
2. **Across-document specificity.**  A term is more informative if it does not appear in almost every document.

Thus TF-IDF is a simple way to say:

> A good keyword should be frequent in this document but not too frequent across the whole corpus.

## Python example: TF-IDF from scratch

```{python}
#| label: ch03-tfidf-from-scratch
#| echo: true
#| eval: false

import numpy as np
import pandas as pd

# X is the document-term count matrix from the previous example.
n, d = X.shape

# Term frequency: length-normalized counts.
doc_lengths = X.sum(axis=1, keepdims=True)
TF = X / doc_lengths

# Document frequency.
df = (X > 0).sum(axis=0)

# Smoothed inverse document frequency.
idf = np.log((n + 1) / (df + 1)) + 1

# TF-IDF matrix.
W = TF * idf

W_df = pd.DataFrame(W, columns=vocab, index=[f"doc_{i+1}" for i in range(n)])
print(W_df.round(3))
```

The resulting matrix has the same shape as the count matrix, but its entries have changed.  Common tokens receive smaller column weights, while more specific tokens receive larger column weights.

## Comparing count vectors and TF-IDF vectors

Count vectors often reward documents that share common terms with the query.  TF-IDF vectors reward documents that share more specific terms.

Suppose the query is

```text
language token prediction
```

A count-vector search might rank a document highly because it contains `language` and `token`.  TF-IDF may increase the importance of `token` if it appears in only a few documents.

This distinction matters in academic settings.  For example, in a corpus of course descriptions, words such as `course`, `students`, and `methods` may appear everywhere.  Words such as `Bayesian`, `topology`, or `transformer` may be more specific.

## The geometry of sparse document vectors

Document vectors often live in very high dimensions.  A vocabulary may contain thousands or millions of tokens, while a single document uses only a small subset.  Therefore, most entries of a document vector are zero.

This creates a sparse geometry:

$$
\#\{j:x_j\ne 0\} \ll d.
$$

Sparse vectors are computationally useful because we do not need to store or multiply by all zero entries.  They are also geometrically interesting.  Two randomly chosen short documents may have no terms in common, which makes their dot product zero.

### Orthogonality in sparse spaces

If two count vectors have disjoint supports, then

$$
x^Ty=0.
$$

For nonnegative vectors, this means their cosine similarity is zero.  In a large vocabulary, many pairs of documents may be nearly orthogonal even if they are topically related but use different words.

For example, the documents

```text
neural network training
```

and

```text
deep learning optimization
```

are semantically related, but a simple bag-of-words model may give low similarity if the exact words do not overlap.  This limitation motivates later chapters on latent semantic analysis, word embeddings, and transformer representations.

## Stop words and projection

A common preprocessing step removes very frequent words such as `the`, `and`, `of`, and `to`.  Mathematically, stop-word removal is a coordinate projection.

Let $S\subseteq \{1,2,\ldots,d\}$ be the set of coordinates corresponding to terms we keep.  The projection map is

$$
P_S:R^d\to R^{|S|},
$$

where

$$
P_S(x)=(x_j)_{j\in S}.
$$

This map discards coordinates.  It can improve retrieval by removing noise, but it can also remove meaningful words in some contexts.  For example, `not` is often a stop word in generic lists, but it is crucial for sentiment analysis.

::: {.math-card}
**Modeling warning.**  Stop-word removal is not universally safe.  It is a projection that may remove coordinates relevant to the task.
:::

## Statistical model behind bag-of-words

The bag-of-words representation can be derived from a multinomial model.

Suppose document $x_i$ has length $m_i$ and is generated by independent draws from a categorical distribution

$$
\theta_i=(\theta_{i1},\ldots,\theta_{id}),
$$

where

$$
\theta_{ij}\ge 0, \qquad \sum_{j=1}^d \theta_{ij}=1.
$$

The probability of observing counts

$$
c_i=(c_{i1},\ldots,c_{id})
$$

is

$$
P(c_i\mid \theta_i)=\frac{m_i!}{c_{i1}!c_{i2}!\cdots c_{id}!}\prod_{j=1}^d \theta_{ij}^{c_{ij}}.
$$

The log-likelihood, ignoring the multinomial coefficient, is

$$
\ell(\theta_i)=\sum_{j=1}^d c_{ij}\log \theta_{ij}.
$$

Maximizing this subject to $\sum_j \theta_{ij}=1$ gives

$$
\widehat\theta_{ij}=\frac{c_{ij}}{m_i}.
$$

Thus the relative-frequency vector is the maximum likelihood estimate of the document's token distribution under this simplified model.

### What the model assumes

The multinomial bag-of-words model assumes:

1. token order is irrelevant;
2. tokens are conditionally independent given $\theta_i$;
3. each document has its own word distribution;
4. dependence between neighboring words is ignored.

These assumptions are false for real language, but they give a mathematically transparent baseline.

## Connection to classification

Document vectors are not only used for retrieval.  They can also be used for classification.

Suppose each document has a label

$$
y_i\in \{1,2,\ldots,K\}.
$$

A linear classifier has the form

$$
f(x_i)=\arg\max_{k\in\{1,\ldots,K\}} \left(w_k^T\phi(x_i)+b_k\right).
$$

Here $\phi(x_i)$ may be a count vector, TF-IDF vector, or another document representation.  The same vectorization step supports logistic regression, support vector machines, naive Bayes, and neural networks.

For binary classification, a common model is

$$
P(y_i=1\mid x_i)=\sigma(w^T\phi(x_i)+b),
$$

where

$$
\sigma(z)=\frac{1}{1+e^{-z}}.
$$

This shows how vector-space NLP connects directly to statistics and machine learning.

## Low-dimensional visualization by SVD

Because document vectors are high-dimensional, we often visualize them by projecting to two dimensions.  A simple method is singular value decomposition.

Let $W\in R^{n\times d}$ be a centered or weighted document-term matrix.  Its singular value decomposition is

$$
W=U\Sigma V^T.
$$

The best rank-$k$ approximation in Frobenius norm is

$$
W_k=U_k\Sigma_kV_k^T.
$$

For visualization, we often use the rows of

$$
U_2\Sigma_2\in R^{n\times 2}
$$

as two-dimensional document coordinates.

## Evaluation of retrieval

A document-vector method is often used for retrieval: given a query, return a ranked list of documents.  To evaluate retrieval, we need relevance judgments.

For a query $q$, let

$$
R(q)\subseteq \{1,2,\ldots,n\}
$$

be the set of relevant documents.  If a system returns the top $k$ documents

$$
A_k(q),
$$

then precision at $k$ is

$$
\operatorname{Precision@}k=\frac{|A_k(q)\cap R(q)|}{k}.
$$

Recall at $k$ is

$$
\operatorname{Recall@}k=\frac{|A_k(q)\cap R(q)|}{|R(q)|}.
$$

Precision measures how many retrieved documents are relevant.  Recall measures how many relevant documents were retrieved.

For course search, advising chatbots, and RAG systems, retrieval evaluation is essential.  A language model can only answer from useful evidence if the retrieval step finds useful evidence.

## AI component: document vectors in RAG systems

Modern retrieval-augmented generation systems often use neural embeddings rather than TF-IDF.  However, the mathematical pipeline is similar:

$$
\text{document} \xrightarrow{\phi} R^p,
\qquad
\text{query} \xrightarrow{\phi} R^p,
\qquad
\text{rank by similarity}.
$$

In classical vector search, $\phi$ may be TF-IDF.  In neural vector search, $\phi$ may be a transformer embedding model.  The retrieval step still depends on geometry: dot products, cosine similarity, nearest neighbors, and ranking.

## Worked example: hand calculation

Consider three documents with vocabulary

$$
V=\{a,b,c,d\}.
$$

Suppose the count matrix is

$$
X=
\begin{bmatrix}
2&1&0&0\\
1&0&2&0\\
0&1&0&3
\end{bmatrix}.
$$

Let the query be

$$
q=(1,1,0,0)^T.
$$

The raw dot-product scores are

$$
Xq=
\begin{bmatrix}
3\\
1\\
1
\end{bmatrix}.
$$

The Euclidean norms are

$$
\|q\|_2=\sqrt{2},
$$

$$
\|X_{1\cdot}\|_2=\sqrt{5}, \qquad
\|X_{2\cdot}\|_2=\sqrt{5}, \qquad
\|X_{3\cdot}\|_2=\sqrt{10}.
$$

Thus the cosine scores are

$$
s_1=\frac{3}{\sqrt{5}\sqrt{2}}=\frac{3}{\sqrt{10}},
$$

$$
s_2=\frac{1}{\sqrt{5}\sqrt{2}}=\frac{1}{\sqrt{10}},
$$

and

$$
s_3=\frac{1}{\sqrt{10}\sqrt{2}}=\frac{1}{\sqrt{20}}.
$$

Therefore, document 1 is most similar to the query.

This small example illustrates the full retrieval calculation: vectorize, multiply, normalize, rank.

## Common pitfalls

### Pitfall 1: confusing rows and columns

Always state whether documents are rows or columns.  In this book, documents are rows.

### Pitfall 2: forgetting zero vectors

Cosine similarity is undefined when one vector has zero norm.  This can happen if a query contains no vocabulary terms.

### Pitfall 3: assuming TF-IDF understands meaning

TF-IDF is a lexical method.  It does not know that `doctor` and `physician` are related unless the corpus and vocabulary create indirect associations.

### Pitfall 4: ignoring corpus dependence

IDF weights depend on the corpus.  If the corpus changes, the IDF weights change.

### Pitfall 5: treating preprocessing as neutral

Lowercasing, punctuation removal, stop-word removal, and stemming all change the mathematical representation.

## Chapter summary

The main construction in this chapter is the document-vector map

$$
\phi:V^*\to R^d.
$$

The simplest choice is the count vector.  From count vectors we build the document-term matrix

$$
X\in R^{n\times d}.
$$

We then transform this matrix using normalization and TF-IDF weighting.  Similarity between documents or between a query and documents is often measured by cosine similarity:

$$
\operatorname{cos}(x,y)=\frac{x^Ty}{\|x\|_2\|y\|_2}.
$$

These ideas form the classical foundation of search and retrieval.  They also prepare us for modern NLP, where documents and queries are represented by learned dense vectors instead of sparse TF-IDF vectors.
